業種別に、何ができるか。

ご依頼の多い4業種を例に、現場で「時間を取られている仕事」と、それに対して何をつくるかをご紹介します。他業種の方も、近い業種を選ぶと導入イメージがつかめます。

見積・段取り・不良判定。工場の利益を左右する判断のほとんどは経験によるもので、その経験はたいてい一人か二人に集中しています。

現場でよく聞く困りごと

  • 図面を見て過去案件を探し、材料費を拾い、工数を積む。見積に半日かかり、それができるのは社長かベテラン1人
  • FAXや紙で届く注文書を、基幹システムに手入力。毎日1〜2時間、転記ミスも出る
  • 「この材質はこの条件で削る」という勘所が文書になっていない。その人が休むと現場が止まる

私たちがつくるもの

  • 図面からの見積たたき台図面・仕様書を読み込ませ、類似案件と材料費・想定工数を並べた下書きを出す。最終判断は人が行う
  • 注文書・伝票の自動転記FAX・PDF・メール本文の注文書を読み取り、基幹システムや管理表に流し込む。人は最後の確認だけ
  • ベテランの知見を聞けるAI手順書・不良記録・日報・写真をひとまとめにし、「この材質のときどうしてた？」と話し言葉で聞ける状態にする

現場が終わってから始まる、事務所の仕事。安全書類・日報・写真整理・積算。残業規制が入っても、書類の量は減っていません。

現場でよく聞く困りごと

  • 施工写真が何百枚もスマホに溜まり、工種ごとの整理と報告書づくりで夜が消える
  • 安全書類・作業計画書・日報が現場ごとに必要で、毎回ほぼ同じ内容を一から書いている
  • 積算・見積が属人化していて、担当者が抜けると受注が止まる

私たちがつくるもの

  • 施工写真の自動整理と報告書生成撮った写真を工種・日付・場所で自動分類し、報告書の下書きまで組み立てる
  • 安全書類・日報の下書きAI過去の書類と工程表から、現場に合わせた書類を自動で下書き。担当者は確認と修正だけ
  • 積算・見積のたたき台過去の実績単価と図面から、積算の下書きを作る。ベテランの単価感を会社の資産にする

問い合わせは増え、媒体は増え、確認すべき書類も増える。反響対応と事務作業に追われて、肝心の接客と現地案内の時間が削られています。

現場でよく聞く困りごと

  • 物件情報を複数のポータルと自社サイトに同じ内容で入力している。更新漏れも起きる
  • 重要事項説明書・契約書の確認が担当者の目視頼みで、時間がかかるうえに見落としが怖い
  • 夜間や休日の問い合わせに返せず、翌朝には他社に決まっている。英語や中国語の問い合わせは対応できていない

私たちがつくるもの

  • 物件情報の自動入力と多媒体配信図面・資料から物件情報を読み取り、各媒体の形式に合わせて出力。入力は一度だけ
  • 契約書・重説のチェックAI過去の書類と照合し、抜け・矛盾・要確認箇所を一覧にする。最終確認は宅建士が行う
  • 問い合わせの一次対応（多言語）物件資料をもとに、メール・LINE・チャットの問い合わせに24時間で下書きを返す。日本語・英語・中国語に対応

ドライバーは足りず、走れる時間は減った。それなのに事務所では、伝票の手入力と荷物の問い合わせ対応が減っていません。

現場でよく聞く困りごと

  • 荷主ごとに形式の違う送り状・伝票を、配車システムに手で打ち直している
  • 配車調整が配車担当の頭の中にしかなく、その人が休むと誰も組めない
  • 「荷物はいまどこ」「何時に着く」の電話が一日中鳴り、事務員が1人つきっきり

私たちがつくるもの

  • 伝票・送り状の読み取りと転記自動化形式が違う帳票でも読み取り、配車・請求システムに流し込む。荷主ごとの追加設定は不要
  • 配車の下書きAI過去の配車実績と当日の荷物・車両・ドライバー条件から、配車案を自動で組む。配車担当は確認と調整だけ
  • 荷物問い合わせの自動応答配送状況と連携し、電話・メール・LINEの「いまどこ」に自動で答える。ドライバー日報の自動作成も対応

PROBLEM
PROBLEM

業種は違っても、AIが引き取る仕事は同じです。

読んで、写しているだけの仕事

注文書、伝票、図面、物件資料。届いたものを見ながら、別のシステムや管理表に人が打ち直している。数えたことはないが、たぶん毎日1〜2時間。転記ミスの確認にさらに時間がかかる。

下書きを、ゼロから積んでいる

見積、積算、日報、報告書、安全書類。過去に似たものを作っているのに、毎回一から。それができるのが社長かベテラン1人で、その間ほかの仕事が止まっている。

答えが、人の頭の中にしかない

加工条件、単価感、配車の組み方、契約の勘所。文書になっていないから、その人が休むと現場が止まり、辞めたらもう戻らない。問い合わせの電話も、その人にしか答えられない。

AIエージェント（業務の自動実行）

画像認識

用途：外観検査／施工写真整理／設備の異常検知／在庫の画像カウント

予測・最適化

SECURITY
SECURITY

図面・契約書・顧客情報は、外に出しません。

「AIに読ませる」と聞いて最初に心配になるのは、自社の図面や契約書、取引先の情報がどこかに送られてしまうことだと思います。当然のご心配です。ここを曖昧にしたまま話を進めることはいたしません。

御社のデータが、御社から出ない作り方ができます。

AIには、外部のサービスに情報を送って処理する方式と、御社の中だけで完結させる方式があります。図面・原価・契約書・顧客情報といった外に出せないものを扱う場合は、後者で構築します。

社内で完結させる構成

御社のサーバーや閉じた環境の中だけでAIを動かす構成を選べます。この場合、データは一切外部に送信されません。

学習に使わせない設定

外部サービスを使う場合も、入力した内容がAIの学習に使われない契約・設定を前提に構築します。

見られる範囲を分ける

原価、取引条件、個人情報など、社内でも一部の方だけが見るべき情報には、閲覧権限を設定します。

秘密保持契約を先に

現場を拝見する前に、こちらから秘密保持契約をお願いします。図面や契約書をお預かりする前提の話をする以上、当然の手順だと考えています。

どの方式が適しているかは、扱う情報の種類とご予算によって変わります。ご相談の段階で、それぞれの違いと費用感を専門用語を使わずにご説明します。「よく分からないまま契約する」ということがないようにいたします。

開発の進め方

要件定義からPoC、本開発、運用まで一気通貫で伴走します。いきなり大きな投資はしません。小さく試して、効くと分かってから広げます。

STEP01

ヒアリングと現場診断無料

工場・現場・事務所に伺い、実際の仕事の流れを見せてください。どこに時間が取られているか、どこならAIが効くかを一緒に探します。この時点で費用はいただきません。売り込みもしません。

STEP02

要件定義と技術選定

「何を、どの技術で、いくらで、どのくらいの期間で作るか」を書面でお出しします。オンプレミスかクラウドか、どのモデルを使うかもここで決めます。効果が見込めないと判断した場合は、正直にそうお伝えします。使える補助金があればあわせてご案内します。

STEP03

PoC（試作と検証／1〜2ヶ月）

いきなり全社に入れず、まず一部の業務・一部の担当者・御社の実データで動かします。精度と使い勝手を数字で確かめてから、本開発に進むかをご判断ください。

STEP04

本開発とシステム実装

効果が確認できたものだけを本開発します。既存の基幹システム・Excel・紙の運用と繋ぎ、現場の担当者がそのまま使える形で実装します。

STEP05

運用支援と改善

納品して終わりではなく、使い方の定着と精度の改善まで伴走します。社内で回せる状態になることをゴールにしています。

よくあるご質問

AIで何ができるのか、正直よく分かっていません。
それで問題ありません。むしろ「何ができるか」を先に考える必要はなく、「いま何に時間を取られているか」だけ教えていただければ十分です。そこからAIで解けるものと解けないものを、こちらで仕分けします。解けないものは、はっきりそうお伝えします。
図面や契約書、顧客情報を外部に出すのは避けたいのですが。
当然のご懸念です。御社のサーバーや閉じた環境の中だけでAIを動かし、データが外部に一切送信されない構成を選べます。外部サービスを使う場合も、入力内容が学習に使われない設定を前提とします。現場を拝見する前に、こちらから秘密保持契約をお願いしております。
オンプレミス（社内サーバー）で構築できますか。
できます。ローカルLLMを御社のサーバーや閉じた環境で動かし、データが一切外部に出ない構成で構築します。クラウド構成と比べた費用感・精度・運用負荷の違いは、要件定義の段階でご説明します。
サイトに載っていない業種ですが、相談できますか。
はい。業種は問いません。現場と事務所のあいだで紙・電話・写真が行き来している会社であれば、同じ作り方が使えます。まずは状況をお聞かせください。お力になれない場合は、その旨を正直にお伝えします。
社内にパソコンに詳しい人間がいません。
現場のある会社では、それが普通だと考えています。導入後に社内の誰かが管理しなければ動かないような作りにはしません。使い方が定着するまで伴走し、分からないことはいつでも聞ける体制にします。
いまのシステムを入れ替える必要がありますか。
原則、必要ありません。既にお使いの基幹システム・配車システム・Excelはそのまま残し、その手前と後ろの手作業をAIが引き取る、という作り方をします。慣れたやり方を変えないことを優先します。
データが紙やExcelにしかありません。
それでも進められます。むしろ紙とExcelしかない会社ほど、整理した瞬間の効果が大きいです。読み取りとデータ化から対応します。
小さな会社ですが、相手にしてもらえますか。
従業員数名の会社こそ、対象だと考えています。大手向けの大きなシステムとは作り方が違い、規模に合わせて小さく作るほうが効果が出やすい領域です。
